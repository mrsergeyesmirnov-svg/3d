# FORMA — AI-ателье 3D-печати

Сайт-концепт: футуристичный магазин с бело-серым Liquid Glass, большим чатом на главной странице, каталогом товаров в стиле премиального магазина и адаптивным дизайном.

Репозиторий: https://github.com/mrsergeyesmirnov-svg/3d

## Уже реализовано

- Главная с чат-консультантом и тремя быстрыми идеями.
- Каталог из 9 позиций, фильтры, карточки, просмотр товара, вход в заказ из карточки.
- Меню: главная, каталог, как это работает, о нас, адреса и доставка.
- Серверный API Yandex AI Studio (OpenAI-compatible Chat Completions).
- Если API-ключ ещё не подключён, работает явно помеченный демо-ответчик; это не настоящая нейросеть.
- Форма заявки прямо внутри чата: изделие, параметры, имя, телефон, доставка.
- Контактные данные и адрес направляются только в российскую PostgreSQL, НЕ в языковую модель.
- Без базы и юридических документов приём реальных заявок заблокирован.
- Иллюстрации товаров являются оригинальными SVG-концептами, не фотографиями готовой продукции.

## Локальный запуск

Нужен Node.js 20+ (рекомендуется Node 22).

    npm install
    cp .env.example .env.local
    npm run dev

Сайт: http://localhost:3000. Проверка типов: npm run typecheck. Сборка: npm run build.

## Настройка Yandex AI

Создайте API-ключ сервисного аккаунта Yandex Cloud с разрешением на вызов генеративной модели и узнайте ID каталога. Добавьте в серверные переменные окружения:

    YANDEX_AI_API_KEY=ваш_секрет
    YANDEX_FOLDER_ID=ваш_folder_id
    YANDEX_MODEL_URI=gpt://ваш_folder_id/yandexgpt/latest

Последняя переменная необязательна. Сервер отправляет сообщения на https://ai.api.cloud.yandex.net/v1/chat/completions с Bearer Authorization. Ключ никогда не должен быть в клиентском JS, NEXT_PUBLIC_ переменных или GitHub.

Документация: https://yandex.cloud/ru/docs/ai-studio/

История диалога на сайте в текущей версии хранится только в оперативной памяти вкладки. Чтобы не собирать лишние персональные данные, чат просит не передавать в переписке адрес, телефон и сведения о здоровье. Контакты и адрес вводятся в отдельную форму заказа.

## Подключение заказов

Перед включением реальных заказов:

1. Развернуть PostgreSQL в РФ; создать таблицу из db/schema.sql.
2. Создать пользователя БД с ограниченными правами, настроить TLS и резервные копии.
3. Заполнить в серверных секретах DATABASE_URL, DATABASE_SSL=true, COMPANY_NAME, PRIVACY_POLICY_URL, SITE_URL.
4. Вместо демонстрационной страницы /privacy опубликовать полноценную политику с реквизитами оператора, сроками обработки, контактами и правами субъектов.
5. Проверить выполнение 152-ФЗ и требований к обработчикам, подключить ограничение частоты API-запросов, защиту от спама и процесс удаления данных.
6. Настроить панель оператора, уведомления по новым заявкам, проверку моделей, оплату и логистику.

Заказ в MVP — ЗАПРОС НА ИЗГОТОВЛЕНИЕ, а не оплаченная покупка. Цена и сроки подтверждаются человеком после проверки модели. Оплата и запуск принтера пока не интегрированы.

## Развёртывание на российском хостинге

Есть Dockerfile для Next.js standalone. Подойдёт российский VPS или Yandex Cloud Serverless Containers / VM с HTTPS-доменом, серверными секретами и доступом к PostgreSQL в РФ.

GitHub Pages для этого проекта не подходит: он не исполняет API-роуты и не хранит секреты безопасно.

Размещение сервера в РФ и использование Yandex AI сами по себе не гарантируют юридическое соответствие: нужны документирование процессов, согласия, договоры, технические и организационные меры.

## FORMA Create — разработка отдельно от печати

Добавленная ценовая логика (плановые цены, не публичная оферта):
- Общение с FORMA AI, выбор готовой модели, персонализация имени/цвета/даты в пределах шаблона: **без платы за разработку**.
- Доработка шаблона: **490–990 ₽** (предварительно от 490 ₽).
- Индивидуальная 3D-модель с нуля: **1 490–3 990 ₽** (предварительно от 1 490 ₽).
- Сложные технические проекты: **от 4 990 ₽**.
- Печать, доставка, передача исходных CAD/STL и коммерческих прав: отдельные условия и расчёт.
- Базовый проект предусматривает одну итерацию согласованных правок; итоговый объём работ оговаривается в ТЗ.

Логика расчёта находится в `lib/design-pricing.ts`. Сервер не доверяет ценам, присланным браузером: по `productId` и `designTier` цена пересчитывается в `app/api/orders/route.ts`. Для новой модели и Studio Prototype стоимость печати обозначается **«По расчёту»**, а не придумывается заранее. Приём платежей не подключён. Демо-интерфейс на GitHub Pages использует аналогичную логику только для предварительного просмотра, не принимает личные данные или оплату.

**Миграция базы:** перед запуском обновлённого API на существующей PostgreSQL обязательно исполнить `ALTER TABLE ... ADD COLUMN IF NOT EXISTS` из `db/schema.sql` для полей `design_tier`, `design_fee_from_rub`, `printing_price_from_rub`; иначе сохранение новой заявки завершится ошибкой.
